# reference/ — パッチ数値の参照プール

チャットでの数値回答に使う**ゲーム内数値の保管庫**。アプリ（frontend / app.py / database）とは完全に独立していて、
アプリのビルドや実行には一切影響しない。ここは「読むだけ」のデータ置き場。

## なぜ必要か

会話が長くなると、過去に苦労して検証した数値（PTAの内部CT、Collectorの現行スタッツ、
征服者の確定ダメージ撤廃など）が失われて、また古い数値で誤答するリスクがある。
それを防ぐために、**一度確定した数値をここに固定し、毎回ここを先に見る**運用にする。

## ファイル構成

| ファイル | 中身 |
|---|---|
| `patch-state.md` | 現在の基準パッチ・最終更新日・未検証項目の一覧 |
| `formulas.md` | ダメージ計算ルール（貫通順序・クリ・固定/割合ダメージ） |
| `aphelios.md` | アフェリオスの基礎ステータス・武器・スキルポイント配分 |
| `items.md` | 検証済みアイテム数値 |
| `runes.md` | 検証済みルーン数値（キーストーン・シャード） |
| `opponents.md` | 対面・敵チャンピオンの数値（射程など） |

## 信頼度マーク（必ず付ける）

数値には必ず信頼度を付ける。出典が割れている数値を「確定」として扱うのが一番危険なため。

- ✅ **確定** — 複数ソース一致、またはクライアント実測済み
- ⚠️ **要検証** — ソース間で数値が食い違っている。使う時は必ず断り書きを添える
- 🔵 **実測提供** — ユーザーがクライアント内で確認した値（最も信頼度が高い）

## 更新ルール

1. 新しい数値を確定させたら、該当ファイルに追記し `patch-state.md` の更新日を直す
2. パッチが上がったら `patch-state.md` の基準パッチを更新し、影響しそうな項目に ⚠️ を付け直す
3. ⚠️ が付いた数値を実測で解決したら 🔵 に格上げして、矛盾していた出典の記述を消す

## 一括更新（DDragonから再生成）

`scripts/fetch_patch_reference.py` がRiot Data Dragonから基礎ステータスを取得して
`reference/generated-*.md` を生成する。

**ただしこのスクリプトはローカル環境で実行すること。** Claude Code の実行環境からは
`ddragon.leagueoflegends.com` へのアクセスがネットワークポリシーで拒否されるため動かない
（アプリはユーザーのブラウザから直接叩いているので影響なし）。

```bash
python scripts/fetch_patch_reference.py
```

生成物（`generated-*.md`）は手書きファイルと分離してあるので、手で書いた検証済みメモが
上書きで消えることはない。

## DDragonでカバーできない数値

以下はDDragonに載っていないので、**手動検証してこのフォルダに書く**しかない：

- ルーンの具体的な数値（`runesReforged.json` は説明文のみで数値なし）
- キーストーンの内部クールダウン
- アイテムパッシブの正確な数値（説明HTMLに埋まっていて機械抽出が不安定）
- ダメージ計算の適用順序・クリティカル倍率などのシステム仕様
